# Implementation Notes: generate-long-descriptions.py

## Overview

This document describes the implementation of the post-deployment script that generates user-friendly long descriptions for agents.

## Task Reference

**Spec:** enhanced-agent-ui  
**Task:** 1.5.7 - Create post-deployment script to generate long descriptions  
**Requirements:** 1.4, 3.2

## What Was Implemented

### 1. Main Script: `generate-long-descriptions.py`

A Python script that:
- Reads stack configuration from `config.yaml`
- Lists all agents from SSM parameters
- For each agent:
  - Fetches source code from S3
  - Extracts docstring and system prompt using regex
  - Invokes the default agent via AgentCore Runtime API
  - Generates a 2-3 sentence user-friendly description
  - Stores the description in SSM: `/{stack}/agents/{agent_name}/long-description`

### 2. Key Features

**Idempotency:**
- Safe to run multiple times
- Uses `put_parameter` with `Overwrite=True`
- No side effects from repeated runs

**Error Handling:**
- Gracefully handles missing source code (logs warning, continues)
- Gracefully handles agent invocation failures (logs error, continues)
- Continues processing other agents if one fails
- Exits with code 1 if any errors occurred

**Logging:**
- Comprehensive logging at INFO level
- Progress indicators for each step
- Summary report at the end
- Clear success/warning/error indicators (✓, ⚠, ✗)

**AWS Integration:**
- Uses boto3 for S3, SSM, and Bedrock AgentCore Runtime
- Supports AWS_PROFILE and AWS_DEFAULT_REGION environment variables
- Proper error handling for AWS API calls

### 3. Extraction Functions

**`extract_docstring(source_code: str) -> str`**
- Extracts module-level docstring from Python source
- Supports both `"""` and `'''` triple-quoted strings
- Handles comments before docstring
- Returns empty string if not found

**`extract_system_prompt(source_code: str) -> str`**
- Extracts `system_prompt` variable from Python source
- Supports both `"""` and `'''` triple-quoted strings
- Handles multi-line prompts
- Returns empty string if not found

## Design Decisions

### 1. Why Post-Deployment Script?

The long descriptions are generated by invoking the default agent, which requires:
- The agent to be deployed and running
- AgentCore Runtime to be available
- Network connectivity to AWS services

This cannot be done during CDK deployment (which is infrastructure provisioning), so a post-deployment script is the appropriate solution.

### 2. Why Invoke the Default Agent?

- Leverages existing AI capabilities to generate descriptions
- Ensures descriptions are user-friendly and well-written
- Maintains consistency in tone and style
- Reduces manual work for developers

### 3. Why Store in SSM?

- Consistent with existing agent metadata storage pattern
- Easy to retrieve via agent-discovery Lambda
- No additional infrastructure needed
- Supports updates without redeployment

### 4. Why Regex for Extraction?

- Simple and reliable for well-structured Python code
- No need for full AST parsing
- Handles the specific patterns used in agent files
- Fast and lightweight

### Running the Script

```bash
# From repository root
python infra-cdk/scripts/generate-long-descriptions.py

# With specific profile
AWS_PROFILE=myprofile python infra-cdk/scripts/generate-long-descriptions.py

# With specific region
AWS_DEFAULT_REGION=us-west-2 python infra-cdk/scripts/generate-long-descriptions.py
```
