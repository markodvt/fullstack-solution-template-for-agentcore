Fix multi-agent orchestration: strands-agents-tools dependency

Root Cause Analysis:
The UMich agent was failing with ModuleNotFoundError for 'strands_tools'
because strands_tools comes from a separate package (strands-agents-tools),
not included in strands-agents. This was discovered through local testing
and verification against PyPI package documentation.

The orchestrator agent couldn't invoke specialist agents because:
1. Specialist invocation functions lacked @tool decorators
2. functools.partial objects don't preserve @tool decorator metadata
3. Strands couldn't recognize the tools for LLM invocation

What Was Fixed:
- Added strands-agents-tools>=1.0.0 to all agent requirements.txt files
- Added @tool decorators to specialist invocation functions
- Implemented functools.partial parameter binding (needs wrapper class)
- Fixed SSM parameter name (runtime_arn → runtime-arn)
- Created comprehensive strands.md steering documentation
- Built local testing environment for pre-deployment validation
